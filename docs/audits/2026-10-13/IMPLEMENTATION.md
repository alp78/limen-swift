## Additional iOS dispositions

- Test isolation: Debug uses `dev.peringer.limen.audit`, separate preferences/storage, while Release retains `dev.peringer.limen`. Reset/demo/store overrides are guarded by the audit identity and supported root. Production records must never be deleted to run tests. The final release report must show built identifiers and physical-install evidence.
- Async evidence ownership: deterministic `PhotoIntakeOwnershipTests` passed for same owner ID after another record/amendment is opened, deleted owner, finalization before completion, and cleanup of only the operation's own capture. Successful intake preserves exact bytes/hash and import/capture distinction. Real camera/provider encoding interruptions remain device checks.
- Archive limits: 64 MiB payload, 256 MiB expanded total, 20,000 entries, 8 MiB record JSON, 64 MiB other entries; new photo/supporting-document intake 32 MiB. ZIP parser validates offsets/sizes/local-central consistency and regular files before allocation. Malicious archive, truncation and authentication regressions passed in the combined unit run.
- Privacy/files: private Application Support and staging are excluded from backup and use Data Protection; public documents are intentionally shareable. Temporary staging is private. Physical Files breadcrumb, system permission language and actual protection attributes require the final device/bundle report.
- Previously repaired behaviour is retained: ImageIO orientation, proleptic/date-picker calendars, .background persistence, weighted layout, A4 page geometry, 560-point readable width, signature scaling, GCM authenticated header/padding, cryptographic RNG failure handling, scoped Files access and shipped NOTICE.
